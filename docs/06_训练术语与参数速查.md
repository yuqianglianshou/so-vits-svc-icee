# 训练术语与参数速查

这份文档解释训练页和推理页里最容易混淆的词。

## 1. batch / step / epoch

### batch

一次喂给模型训练的数据量。

- `batch_size=4`：一次用 4 条样本算一次梯度。
- batch size 越大，显存占用越高。
- 显存不足时优先降低 batch size。

### step

模型更新一次参数，记为一个 step。

- 训练日志里的 step 更能反映实际训练进度。
- `G_10000.pth` 里的 `10000` 通常表示训练到约 10000 step 保存的模型。

### epoch

把训练集完整看一遍，记为一个 epoch。

同样的 epoch 在不同数据集上不可直接比较：

- 数据少：一个 epoch 很快，step 少。
- 数据多：一个 epoch 更久，step 多。

## 2. 该看 step 还是 epoch

验收模型时更建议看 step 和听感。

原因：

1. step 更接近模型实际更新次数。
2. 不同数据集的 epoch 含义差异很大。
3. 最终是否好听，仍要靠推理样例验收。

## 3. G_*.pth 是什么

`G_*.pth` 是主模型生成器 checkpoint。

常见例子：

```text
G_10000.pth
G_20000.pth
G_30400.pth
```

一般可以优先试最新的 `G_*.pth`，但不是越新必然越好。如果后期过拟合，较早 checkpoint 可能更自然。

## 4. 音质增强和音色增强

### 音质增强

主要提升声音细节、清晰度和自然度。当前通常对应扩散链路。

相关文件常见位置：

```text
model_assets/workspaces/<model_name>/diffusion/*.pt
model_assets/workspaces/<model_name>/diffusion/config.yaml
```

### 音色增强

主要让声音更贴近目标音色。当前通常对应特征检索 / 索引文件。

相关文件常见位置：

```text
model_assets/workspaces/<model_name>/feature_and_index.pkl
```

## 5. 变调

推理时调整音高。

- `0`：不变调。
- 正数：升调。
- 负数：降调。

建议：

1. 先从 `0` 开始。
2. 男声转女声通常升调。
3. 女声转男声通常降调。
4. 每次小幅调整，不要一上来设很极端。

## 6. 特征检索混合比例

用于控制音色增强参与程度。

- 比例高：更贴目标音色，但可能糊字。
- 比例低：更保留输入清晰度，但音色可能不够像。

建议起点：

```text
0.3 - 0.5
```

如果咬字变糊，降低；如果音色不像，提高。

## 7. 浅扩散步数

用于扩散增强。

- 步数高：细节可能更好，但推理更慢。
- 步数低：推理更快，但增强有限。

建议：

1. 快速试听用较低步数。
2. 正式导出用较高步数。
3. 如果开启扩散后更怪，先关闭扩散对比主模型结果。

## 8. num_workers

DataLoader 取数进程数。

- 太低：GPU 可能等数据。
- 太高：Windows 上可能启动慢或更不稳定。

Windows 推荐先从 `4` 左右尝试。若 `all_in_mem=true`，通常设为 `0` 更稳。

## 9. 训练页 1-6 步速记

1. 重采样：统一音频采样率和目录。
2. 配置与列表：生成训练配置和数据列表。
3. 提取特征：提取 ContentVec、F0、音量等训练特征。
4. 主模型训练：训练 `G_*.pth`。
5. 扩散训练：训练音质增强模型。
6. 训练索引：生成音色增强检索文件。

更完整解释见 [训练流程与原理说明](04_训练流程与原理说明.md)。

## 10. 一句话记忆

- ContentVec：唱了什么。
- RMVPE：唱到多高。
- `G_*.pth`：生成目标声音。
- 扩散：提升质感。
- 索引 / 检索：更贴近目标音色。
- batch size：显存压力。
- step：模型实际更新次数。
