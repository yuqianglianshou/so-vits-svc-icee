# Windows 常见问题排查

这份文档专门处理 Windows + NVIDIA GPU 环境下的常见问题。正常操作流程请看：

- [Windows 安装、训练与推理指南](01_Windows安装训练推理指南.md)

## 1. 安装与环境问题

### 1.1 `python` 不是 3.11

现象：

- `python --version` 显示的不是 3.11。
- 创建 `.venv311` 后依赖安装异常。

处理：

1. 先确认系统能找到 Python 3.11：

```powershell
py -3.11 --version
```

2. 用明确版本创建虚拟环境：

```powershell
py -3.11 -m venv .venv311
.venv311\Scripts\activate
python -m pip install --upgrade pip setuptools wheel
```

3. 如果 `py -3.11` 不存在，重新安装 Python 3.11，并勾选 Add Python to PATH。

### 1.2 PowerShell 不允许激活虚拟环境

现象：

- 执行 `.venv311\Scripts\activate` 时报 execution policy 相关错误。

处理：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

关闭 PowerShell，重新打开后再执行：

```powershell
.venv311\Scripts\activate
```

### 1.3 `pip install -r requirements.txt` 失败

先做三件事：

```powershell
python -m pip install --upgrade pip setuptools wheel
pip cache purge
pip install -r requirements.txt
```

如果是网络超时：

1. 换网络。
2. 多执行一次安装命令。
3. 单独安装失败的包，看具体报错。

如果是编译失败：

1. 确认使用 Python 3.11。
2. 确认已经安装最新 `pip setuptools wheel`。
3. 尽量不要用过新的 Python 大版本。

### 1.4 `.bat` 提示找不到 `.venv311`

现象：

- 双击 `launchers/启动训练界面.bat` 或 `launchers/启动推理界面.bat` 后提示未检测到虚拟环境。

处理：

1. 确认虚拟环境在项目根目录：

```text
so-vits-svc-icee/.venv311/
```

2. 如果没有，回到项目根目录创建：

```powershell
py -3.11 -m venv .venv311
.venv311\Scripts\activate
pip install -r requirements.txt
```

## 2. CUDA 与显卡问题

### 2.1 `torch.cuda.is_available()` 输出 `False`

验证命令：

```powershell
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'no cuda')"
```

处理：

1. 确认电脑是 NVIDIA 显卡。
2. 更新 NVIDIA 驱动。
3. 确认安装的是 CUDA 版 PyTorch：

```powershell
pip install -U torch torchaudio --index-url https://download.pytorch.org/whl/cu118
```

4. 重新打开 PowerShell，激活 `.venv311` 后再验证。

### 2.2 `nvidia-smi` 不存在或看不到显卡

处理：

1. 重新安装 NVIDIA 官方驱动。
2. 重启电脑。
3. 在 PowerShell 执行：

```powershell
nvidia-smi
```

如果 `nvidia-smi` 仍不可用，先不要继续训练，优先修显卡驱动环境。

### 2.3 显存不足

常见现象：

- `CUDA out of memory`
- 训练刚启动就退出
- batch size 稍大就报错

处理：

1. 降低 batch size。
2. 先减少训练数据量做小闭环验证。
3. 先只跑主模型训练，扩散训练后面再补。
4. 关闭浏览器游戏、视频软件、其他深度学习进程。
5. 重启 Python / 训练页，释放残留显存。

## 3. 训练前依赖与底模问题

### 3.1 ContentVec HF 一直提示缺失

检查目录：

```text
model_assets/dependencies/encoders/contentvec_hf/
```

必须同时存在：

```text
config.json
model.safetensors
```

只放一个不算完整。训练页会显示具体缺哪个。

处理：

1. 在训练页“选择依赖”里选择 ContentVec HF。
2. 优先点“自动获取当前依赖”。
3. 如果手动下载，确认文件名就是 `config.json` 和 `model.safetensors`。
4. 不要把两个文件放到更深一层目录里。
5. 导入后点击“刷新依赖状态”。

### 3.2 `config.json` 下载成网页或文本内容不对

现象：

- 文件名是 `config.json`，但内容像网页。
- 页面仍提示 ContentVec HF 异常。

处理：

1. 使用训练页给出的直链。
2. 浏览器打开成文本页时，右键另存为 `config.json`。
3. 确认文件内容是 JSON，不是 HTML。

### 3.3 `model.safetensors` 下载不完整

现象：

- 文件体积明显很小。
- 下载中断后仍被复制到了目录里。

处理：

1. 删除不完整的 `model.safetensors`。
2. 重新用训练页自动获取。
3. 或手动下载完成后再导入。

### 3.4 RMVPE 提示损坏

原因通常是：

1. `rmvpe.pt` 文件太小。
2. 下载中断。
3. 放错文件，例如把 zip 里的其他文件当成模型。

处理：

1. 在训练页选择 RMVPE。
2. 优先点“自动获取当前依赖”。
3. 如果手动下载 `rmvpe.zip`，解压后导入其中的模型文件。
4. 导入后点击“刷新依赖状态”。

### 3.5 NSF-HIFIGAN 仍然缺失

检查目录：

```text
model_assets/dependencies/vocoders/nsf_hifigan/
```

目录里至少应有声码器模型和配置文件。训练页会检查必要文件。

处理：

1. 在训练页选择 NSF-HIFIGAN。
2. 优先点“自动获取当前依赖”。
3. 手动导入时建议直接导入 `nsf_hifigan_20221211.zip`。
4. 如果手动解压，确认不是多套了一层 `nsf_hifigan/nsf_hifigan/`。

### 3.6 G_0 / D_0 / model_0 缺失

对应含义：

1. `G_0.pth`：主模型生成器底模。
2. `D_0.pth`：主模型判别器底模。
3. `model_0.pt`：扩散底模。

处理：

1. 在训练页逐项选择缺失底模。
2. 点击“自动获取当前依赖”。
3. 若手动导入，确认文件名完全匹配：
   - `G_0.pth`
   - `D_0.pth`
   - `model_0.pt`

## 4. 训练页与浏览器问题

### 4.1 页面没有自动打开

处理：

1. 看启动窗口里的本地地址。
2. 手动在浏览器打开。
3. 常见训练页地址类似：

```text
http://127.0.0.1:7861
```

如果端口被占用，页面可能会换端口，以终端输出为准。

### 4.2 点击“打开训练监控”没立刻打开

当前逻辑会先启动 TensorBoard，再等端口就绪后打开浏览器。

处理：

1. 看训练页“运行提示”。
2. 如果显示“训练监控正在启动中”，等待一会儿。
3. 手动访问：

```text
http://127.0.0.1:6006
```

4. 如果没有曲线，确认训练任务已经产生日志。

### 4.3 点击“进入推理界面”没立刻打开

处理：

1. 看训练页“运行提示”。
2. 如果显示“推理页面正在启动中”，等待一会儿。
3. 如果浏览器没有自动打开，复制提示里的本地地址手动访问。
4. 不要反复快速点击，避免同时启动多个推理页。

### 4.4 页面按钮灰掉或不能点击

常见原因：

1. 当前有训练任务正在运行。
2. 前置步骤还没完成。
3. 依赖或数据还不完整。

处理：

1. 看“当前进度”和“开始前检查”。
2. 等当前任务结束，或点击“停止当前任务”。
3. 补齐页面提示的缺失项。
4. 点击“更新任务状态”。

## 5. 数据导入问题

### 5.1 导入后 wav 数量是 0

检查：

1. 文件是否真的是 `.wav`。
2. 是否导入到了当前模型绑定的数据目录。
3. 文件是否在多层子目录里。
4. 文件名是否包含异常字符。

处理：

1. 重新导入少量 wav 做测试。
2. 文件名先改成简单英文或数字。
3. 点击“刷新语音数据”。

### 5.2 数据目录结构不符合规则

当前推荐：

```text
training_data/source/<model_name>/*.wav
training_data/processed/44k/<model_name>/
```

不要把多个说话人的目录混在同一个模型目录里。

### 5.3 音频质量不好

训练前尽量避免：

1. 伴奏。
2. 大混响。
3. 多人说话或合唱。
4. 噪声明显。
5. 音量忽大忽小。

如果数据质量差，模型训练正常也可能效果差。

## 6. 训练步骤问题

### 6.1 第 1 步重采样失败

检查：

1. 原始 wav 是否可播放。
2. 文件路径是否过长。
3. 文件名是否包含特殊符号。
4. 磁盘是否有空间。

处理：

1. 先用 1-3 个短 wav 测试。
2. 文件名改成简单英文。
3. 重新导入后再跑第 1 步。

### 6.2 第 2 步配置与列表生成失败

检查：

1. 第 1 步是否已经完成。
2. 处理后目录是否有 wav。
3. 当前模型工作区名称是否合法。

处理：

1. 点击“更新任务状态”。
2. 看最近日志里的具体错误。
3. 必要时删除当前处理后数据，重新从第 1 步开始。

### 6.3 第 3 步提取特征失败

常见原因：

1. ContentVec HF 缺失。
2. RMVPE 缺失或损坏。
3. CUDA / 显存问题。
4. 某个音频文件异常。

处理：

1. 先确认训练前依赖全部已存在。
2. 用少量 wav 复现。
3. 查看最近日志中最后一个处理到的文件。
4. 如果总是同一个 wav 失败，先移除该文件。

### 6.4 主模型训练启动后很快退出

检查：

1. 第 3 步是否完整完成。
2. 处理后目录是否有 `*.train.pt`。
3. `G_0.pth` / `D_0.pth` 是否存在。
4. CUDA 是否可用。
5. batch size 是否过大。

处理：

1. 降低 batch size。
2. 重新跑第 3 步。
3. 看日志尾部的具体报错。

### 6.5 扩散训练失败

检查：

1. `model_0.pt` 是否存在。
2. 第 3 步是否生成扩散训练需要的特征。
3. 显存是否足够。

处理：

1. 先确认主模型训练能跑。
2. 再单独跑扩散训练。
3. 显存紧张时先跳过扩散，完成主链路验证。

### 6.6 音色增强索引训练失败

检查：

1. 第 3 步是否完成。
2. 特征文件是否存在。
3. 数据量是否太少。

处理：

1. 先完成主模型训练和推理验证。
2. 再补索引训练。
3. 数据太少时，索引收益也有限。

## 7. 推理页问题

### 7.1 加载模型失败

检查：

1. `G_*.pth` 是否存在。
2. 同一模型工作区下是否有 `config.json`。
3. 如果启用扩散，扩散 `.pt` 和 `config.yaml` 是否匹配。
4. 如果启用音色增强，`.pkl` 是否属于当前模型。

处理：

1. 先只加载主模型和配置。
2. 成功后再逐个打开扩散和音色增强。
3. 不要混用不同模型工作区的文件。

### 7.2 转换开始后报错

检查：

1. 输入音频是否可播放。
2. 输入文件是否太长。
3. 变调参数是否极端。
4. 显存是否不足。

处理：

1. 先用 15-30 秒短音频测试。
2. 先关闭扩散和音色增强。
3. 成功后再逐步打开高质量选项。

### 7.3 输出文件找不到

默认输出目录：

```text
inference_data/outputs/
```

处理：

1. 看推理页的输出路径提示。
2. 点击页面输出文件链接。
3. 确认当前运行目录是项目根目录。

## 8. 音质与效果问题

### 8.1 声音跑调

处理：

1. 确认使用 RMVPE。
2. 唱歌场景谨慎使用自动 F0。
3. 检查变调参数是否正确。
4. 输入音频本身音准差时，输出也会受影响。

### 8.2 咬字差但音色像

处理：

1. 降低音色增强 / 检索比例。
2. 换更干净的输入音频。
3. 训练数据里增加清晰咬字样本。
4. 不要过度依赖扩散掩盖主模型问题。

### 8.3 电音感明显

处理：

1. 检查训练数据质量。
2. 降低过高的增强比例。
3. 尝试不启用扩散做对比。
4. 确认 ContentVec / RMVPE 依赖完整。

### 8.4 底噪明显

处理：

1. 换更干净的训练数据。
2. 换更干净的输入音频。
3. 减少带噪样本。
4. 对比开启和关闭扩散后的差异。

### 8.5 音色不像

处理：

1. 增加目标说话人 / 歌手数据量。
2. 确保数据是单说话人。
3. 不要混入其他人声音。
4. 检查推理页是否加载了正确模型工作区的 `G_*.pth`。

## 9. 日志怎么看

训练页主要看三个位置：

1. “开始前检查”：看缺少什么依赖、数据或前置步骤。
2. “当前进度”：看每个训练阶段是否完成。
3. “最近日志”：看最后的错误信息。

排查时优先复制：

1. 报错最后 20-50 行。
2. 当前执行的阶段。
3. 当前模型工作区名。
4. 是否 CUDA 可用。
5. 依赖状态截图或文字。

## 10. 什么时候建议从头重来

以下情况建议新建一个模型工作区做小闭环：

1. 多个说话人数据混到一起。
2. 处理后目录结构已经乱了。
3. 不确定当前模型用了哪批数据。
4. 同一模型工作区里混入了不同配置或旧产物。

推荐方式：

1. 新建模型工作区。
2. 只导入 3-5 条干净短 wav。
3. 跑 1-3 步。
4. 启动主模型训练确认能产出 `G_*.pth`。
5. 进入推理页做短音频转换。

这个小闭环能跑通，再回到完整数据集训练。
