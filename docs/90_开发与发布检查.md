# 开发与发布检查

本文面向维护者，定义无需模型权重的静态检查和需要真实 Windows/NVIDIA 环境的人工验收。

## 1. 安装开发依赖

在项目虚拟环境中运行：

```bash
python -m pip install -r requirements-dev.txt
```

## 2. 静态检查

```bash
python -m ruff check scripts/check_release.py tests
python -m compileall -q src scripts tests
python scripts/verify_app_smoke.py
python scripts/verify_stability_fixes.py
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest tests -q
python scripts/check_release.py
```

`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` 用于隔离运行环境中与本项目无关的 pytest 插件。当前项目虚拟环境可能包含旧版 Hydra 插件，该插件与 Python 3.11 不兼容，但不参与项目测试。

当前 Ruff 门禁覆盖发布检查器和测试代码。核心源码尚有历史格式与导入顺序问题，将在后续工程重构中单独治理，避免发布稳定化阶段引入大范围无关改动。

## 3. 发布检查器覆盖范围

`scripts/check_release.py` 检查：

- README 和 docs 的仓库内链接。
- 训练页、推理页、配置模板和 Windows 启动脚本。
- JSON 和 YAML 配置模板是否可解析。
- Git 是否误跟踪模型、生成音频、虚拟环境或缓存。

该脚本不下载模型、不运行 CUDA，也不能替代真实训练和推理验收。

## 5. Release Candidate 规则

以下条件全部满足后才能生成发布候选：

1. 静态检查全部通过。
2. README、Issue 模板和文档不再引用上游旧支持入口。
3. 没有误提交模型、音频、日志、虚拟环境或缓存。
4. 未改变模型结构、默认训练参数和文件格式。

Windows 人工验收完成前，不应把版本描述成已在所有目标环境完成验证。
